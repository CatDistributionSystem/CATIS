# CDS-OPS-009

## 系统通信的编制与发布

**文件状态：** 已批准  
**文件系列：** 操作程序  
**修订版本：** 7e42.12  
**负责机构：** Cat Distribution System (CDS)

### 1. 目的

本程序确立规范 Cat Distribution System (CDS) 正式通信编制、审查、登记和发布的原则及行政要求。

其目的在于确保系统通信形式一致、符合预定用途，并得到适当记录。

### 2. 适用范围

本程序适用于系统正式通信，包括：

- 系统通知。
- 行政指令。
- 操作说明。
- 正式请求和通知。
- 行政函件。
- 以系统名义发布的其他通信。

本程序既适用于内部行政用途的通信，也适用于发给外部个人或实体的通信。

本程序不确立任何特定通信的实质权限，也不披露系统运行所依据的内部机制。

### 3. 一般原则

#### 3.1 准确性

通信应准确表达其拟传达的信息、决定或指示。

未经确认的信息不得作为既定事实呈现。

#### 3.2 清晰性

通信应使用清楚、明确且适合预定接收对象和用途的语言。

#### 3.3 一致性

正式通信应遵循既定的 CDS 术语、文件规范及适用的语言要求。

#### 3.4 适当披露

通信内容应限于适合其预定接收对象的信息。

除非已明确授权披露，否则不得在公开通信或对外分发的通信中包含受限信息。

#### 3.5 行政记录

已发布的通信应以便于识别和日后查阅的方式予以记录。

### 4. 通信类型

出于行政管理目的，系统通信可分为以下类别。

**4.1 系统通知**

用于公布相关信息、行政情况变化或需要接收方知悉事项的通信。

**4.2 行政指令**

为特定行政目的确立指示或要求的正式通信。

**4.3 操作说明**

就操作活动的执行或协调提供指导的通信。

**4.4 请求与通知**

用于请求信息、确认情况或向接收方告知相关进展的通信。

**4.5 行政函件**

为维持与系统相关的行政活动连续性所必需的其他正式通信。

通信分类应反映其实际用途，不应暗示超出其明确范围的权限。

### 5. 编制

编制通信时应考虑：

- 预定目的。
- 预定接收对象。
- 拟传达的信息。
- 接收方可能需要采取的行动或作出的答复。
- 适用的披露限制。
- 相关支持文件。
- 适当的通信类别。

如通信引用现有案件、指令或文件，在适当情况下应列明相关编号或引用信息。

草稿通信应能够与已发布的通信区分开来。

### 6. 审查与批准

通信发布前，应审查以下事项：

- 信息准确性。
- 术语一致性。
- 清晰性和完整性。
- 分类是否适当。
- 预定接收对象是否正确。
- 是否符合适用的披露限制。
- 是否与相关系统文件保持一致。

如需批准，在获得批准之前，不得将该通信视为已正式发布。

适用的批准要求取决于通信的性质及其预定用途。

### 7. 登记与识别

在需要时，正式通信应获得适当的行政编号或引用标识。

登记记录在适用情况下应包括：

- 唯一通信编号。
- 通信类别。
- 标题或主题。
- 发布状态。
- 预定接收对象或分发范围。
- 相关文件引用。
- 适用的语言版本。
- 任何确认收悉或答复要求。

通信登记本身不构成通信的发布。

### 8. 发布与分发

经批准的通信可通过适当的分发方式发布，该方式应符合通信的预定目的和接收对象。

分发方式可包括：

- 直接发送给指定接收方。
- 列入行政通信登记册。
- 通过获授权的信息渠道发布。
- 通过其他适当方式传递。

分发方式应考虑通信的分类及披露要求。

如要求确认收悉，应明确说明该要求。

未收到确认收悉，不应自动视为通信未被接收。

### 9. 语言与版本

系统通信应遵循适用的 CDS 语言规范。

如发布多个语言版本，各版本应传达实质内容相等的信息。

除非另有明确规定，语言版本之间出现差异时，以英文版本为准。

译文应保留原通信的预期含义、分类及行政效力。

### 10. 修订、撤回与取代

在情况需要时，已发布的通信可予以修订、撤回或取代。

任何此类操作均应予以记录，并在适当情况下通知原接收方。

记录应保留原通信与其后续版本或替代文件之间的关联。

修订后的通信不应掩盖原通信的存在或其先前状态。

### 11. 记录维护

已发布通信的记录应按照适用的 CATIS 文件规范予以维护。

行政记录在适用情况下应保存：

- 最终发布版本。
- 登记编号。
- 批准状态。
- 发布和分发信息。
- 适用的语言版本。
- 后续修订或撤回记录。
- 相关收悉确认和答复。

如草稿和工作材料与通信的行政沿革有关，可予以保留。

### 12. 公开通信与受限通信

拟公开分发的通信只能包含获准公开的信息。

受限通信应按照适用的访问和披露要求进行处理。

如受限通信的标题或内容本身也属于受限信息，可在适当登记册中记录其存在，而不披露其标题或内容。

公开确认某项通信的存在，并不意味着公众可以访问其底层内容。

### 13. 行政限制

本程序规范系统通信的行政处理。

本程序本身不确立指令的实质权限，不确定外部各方的义务，也不授权披露受限信息。

不得将通信解释为证明其内容未明确确立的其他情况。

### 14. 最终条款

通信应根据其目的编制，根据其分类发布，并根据其行政重要性予以保存。

编制通信不等于批准。登记不等于发布。发布不等于确认收悉。

**正式通信是系统行政记录的一部分，而不是对系统本身的披露。**
